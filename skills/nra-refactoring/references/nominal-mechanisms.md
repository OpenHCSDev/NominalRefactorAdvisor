# Choosing a nominal mechanism from the domain obligation

These are **candidate mechanisms and falsifiers**, not a pattern→rewrite table. The user supplied string-status, dict-bag, flag-avalanche, god-manager, exception-routing, autoregistering-value, explicit-state and MRO-mixin examples as the desired *structural direction*. The agent must apply the [owner-finding procedure](finding-owners.md), name the admitted required answers, and choose only the mechanism that actually represents them. Do not make the user perform that trace or treat the illustrative snippets as proven repairs.

| Source lead | Candidate owned structure | What must be true / negative control |
|---|---|---|
| Raw status strings and repeated `if status == ...` | For behavior-bearing states, prefer a **public state ABC** with substitutable case-specific classes owning their data, invariants and transitions; inherit common algorithms. An **Enum** is appropriate when it has an independently justified value-only or boundary-vocabulary role, not merely because the family is small. Consumers invoke the public behavior contract rather than reinterpreting tags. | Preserve legal/illegal transitions, order, unknown persisted strings and wire spellings. An ordinary method defined on the Enum **class** is shared by every member: hiding `if self is Status.PENDING` inside it is still a switch. `Enum` + handwritten `ALLOWED_STATES` + remaining switches is a mirror, not polymorphism. A list of allowed next classes can itself be an independently writable transition graph: attach each edge to a declared owner or derive it if another relation determines it. No subclass solely because a string appears. |
| Nested `payload["address"]["country"]`, scattered shape guards | Use an explicit decoder/factory or authored constructor/`__post_init__` to parse and validate a **domain value object/dataclass** at the external boundary; domain behavior stays with the object, serialization remains an adapter. If variants have distinct public obligations, introduce a meaningful ABC and children. | A local dict or an external wire schema can be appropriate. ## ABC, MI, metaclass: choose the narrowest justified class-level tool

- **ABC polymorphism:** Use when consumers require one named public contract and cases provide meaningfully different, substitutable behavior. Put common validation/template logic on the parent; put only varying hooks on children. A subclass set or `__subclasses__()` census is not automatically closed or import-stable. Verify every required `(implementation, consumer/class)` pair, including the missing and forbidden distinctions, before claiming coverage. Generic consumers call the parent contract; serialization or UI remains a separate adapter where appropriate.
- **Multiple inheritance:** Use only when two independently meaningful capabilities must compose on the same object and native C3 lookup expresses the admitted precedence. Explicitly check method resolution, `super()` chains, cooperative constructors, overlapping attributes/slots, decorators and required behavior across the descendant cohort. The order `ValidationMixin, NotificationMixin, BaseCommand` is an observable policy, not a syntactic way to erase three booleans. If two capabilities are not truly independent, factor shared implementation in one parent instead.
- **Metaclass/registration:** Use when the *class declaration itself* must enforce a contract or register a discoverable family at class-creation time. Registry entries should be **derived from the declared identity**, with collision/alias/abstract-class rules owned at that boundary; consumers should not maintain a second handwritten roster. Check `ABCMeta` compatibility, inherited registration keys, C3/metaclass conflict, class-body/decorator execution, dynamic imports, mutation and unknown-name behavior. A metaclass that invents keys with `name.lower().replace("value", "")`, uses `hasattr` to infer inherited registry state, or silently ignores unknown payload keys can recreate the exact stringly ambiguity it purported to fix. #60 already had `AutoRegisterMeta` elsewhere before independent family/policy specs were removed: metaclasses do not automatically solve mirror ownership.

## What the epoch-defining PR sources actually teach

These are selected **primary Git before/after source** contrasts, not PR-title endorsements or equivalence certificates. Reinspect the stated revisions when transferring a mechanism; retained exceptions are often the important lesson.

- **#38 memory conversion, merge `05eb87f07` `^1→^2`:** Before, `core/memory/converters.py` already validated types from `MemoryType` but used repeated source/target branches and accepted `allow_cpu_roundtrip`. After, `MemoryType` gains a converter property and `to_X` methods are attached **dynamically at import time**; a `MemoryTypeConverter` ABC declares four hooks. `conversion_helpers.py` still maintains an Enum-keyed `_OPS` table of expression strings evaluated with `eval`; `CPU_MEMORY_TYPES`/`GPU_MEMORY_TYPES` are authored classifications, while `SUPPORTED_MEMORY_TYPES`/`VALID_MEMORY_TYPES` derive from these and the Enum. Broad DLPack exception→CPU fallback and the missing `allow_cpu_roundtrip` argument are parity questions. **Lesson:** Enum + ABC + generated methods can compress a cross-product, yet neither static membership nor one-edit extension follows. An agent must distinguish authored policy facts from derived sets and test both a new memory type and failure behavior.
- **#44 widget capability, merge `05d1a32f` `^1→^2`:** The child `ValueGettable`/`ValueSettable` ABCs and `WidgetDispatcher` implement an actual capability boundary for get/set; a combined Qt/ABC metaclass supports manager declarations. But `WidgetService.clear_widget_to_default_state` still switches on Qt types and changes the final fallback from guarded `hasattr(clear)` to unguarded `clear()`. `WidgetMeta` registration warns and **overwrites** duplicate widget IDs despite its fail-loud prose. **Lesson:** ABC polymorphism may be right for one operation while a UI adapter retains another dispatch; metaclass collision policy must be read from execution, not docstrings.
- **#58 state, PR-branch step `43a6cba5b`:** `ObjectState` stores parameters, defaults, nested states, user-set/reset fields and saved baselines; PFM later forwards five direct properties. A sixth uses dynamic `getattr`; callers separately create/look up states and nested managers pass a distinct nested state. **Lesson:** state extraction can remove UI-owned model storage, but neither a common field spelling nor a lifecycle docstring proves all paths share one object.
- **#60 CellProfiler, direct step `5a57218b3→63f0ede15`:** `CellProfilerModule(ABC, metaclass=AutoRegisterMeta)` owns module name, aliases, settings and hooks; `__init_subclass__` validates declarations and duplicate names. `ScopedMeasurementModule(ImageMeasurementInputModule, ObjectMeasurementInputModule)` composes two cooperative `measurement_artifact_inputs` implementations through C3. Semantics derive from backend registration **and separately** `SetupModuleCompiler`; unknown names and selected trait projections remain distinct checks. **Lesson:** MI can express overlapping admitted capabilities rather than a giant switch, but actual MRO output order, registry discovery, aliases and setup/unknown behavior are obligations.
- **#69 materialization, merge `b5abe6aa6` `^1→^2`:** Old `MaterializationSpec(handler: str, options: dict)` selected a registered string handler. New frozen `CsvOptions`/`JsonOptions` compose `FileOutputOptions`, `SourceOptions`, `TabularExtractionOptions` by MI; `MaterializationSpec` rejects raw dict/unregistered option types and `materialize` dispatches by `type(opt)`. `_WRITERS_BY_OPTIONS` is still populated by **explicit** `register_single_file_writer`/`@writer_for` calls carrying a separate `MaterializationFormat`, not automatically discovered by a naming convention as PR prose suggests. **Lesson:** typed data and type-keyed dispatch are gains, but test a new output type across option declaration, writer registration and format label before claiming a single determining owner.

**Naming is not ownership.** A new `FooAuthority`/`FooDeclaration` wrapper that only forwards facts is a tautological layer. Prefer the domain name (`OrderState`, `Address`, `CellProfilerModule`, `ObjectState`) and demonstrate which formerly independent answer or operation it now determines. Equally, not every raw list in logic is wrong: a derived local `choices_set` or an intentionally independent UI subset is not a manual duplicate of all domain elements.

**Finish with a falsifier:** add one new case/field/capability, change an alias, and feed an unknown external value. List every authored edit required before and after. If a second roster, caller-side switch or fallback still has to be kept manually in sync, the proposed polymorphism/metaclass/MI has not provided the claimed maintenance factoring. Then use NRA's existing staged DSL and separate native/behavior proof gates; no illustrative design is an equivalence certificate.
