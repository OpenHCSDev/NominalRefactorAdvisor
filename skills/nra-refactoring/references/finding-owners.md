# Finding the determining owner, not just a matching class

**The agent performs this entire investigation** and delivers the proposed owner and source receipts; it does not give the user steps 1–4 as homework. This is a skill workflow, not a new NRA detector or semantic authority. Fix checkout/import roots, source revision, domain boundary and unknown/dynamic exclusions. Reuse NRA `SourceModule`, `ModuleSyntaxIndex`, canonical class-family index, lexical bindings, original Call/product-flow and existing detector evidence. Never build a competing parser, call registry or nominal roster. Record supplied domain rules and task-authorized specifications/declarations, then select a bounded **source/revision/import-root corpus**, using user scope or cheap search to find candidate modules. Source discovery need not wait for a complete relation, but it must not override supplied intent. Expand contextual scans when a proposed owner depends on other modules.

## 1. Bound the corpus; census classes first

Use existing NRA observations/findings, exact-string matches, substring overlap, helper prefixes and targeted search to select or rank a source corpus. False positives are acceptable retrieval evidence. **Before interpreting any hit**, collect *every original* `ast.ClassDef` row using NRA's `module_syntax_index(parsed.module).indexed_nodes_of_type(ast.ClassDef)` (one existing parse/syntax authority). Join only eligible, uniquely matched declarations to the canonical compact class-family index for indexed ancestry, ABC/Enum/dataclass roles, fields and methods. Its admission traversal covers direct module/class-body declarations, **not** function-nested or conditional/control-flow classes. Preserve those and ambiguous/unmatched original `ClassDef` rows as explicit unprojected OPEN, never invented indexed owners. Keep index-admitted and unprojected classes with no matching string/helper as alternative-owner/counterevidence rows. The agent, not the user, proposes additional candidate domain questions **after** this declaration census and residual overlay, without replacing questions already fixed by the supplied contract. Examples: “What input label keyword does this CellProfiler module require?”, “Which setting value type is accepted?”, or “Who owns the saved parameter state?” List cases/states and externally observable answers, including unknown input and errors. A class, filename, repeated string or inferred pattern is not itself the question. The same value may answer different questions at different phases (wire schema vs parsed domain vs UI presentation).

## 2. Overlay residual syntax on the complete class census

Retain original definition order, decorators, defaults, class-body/module rebinding and registered declarations for all index-admitted classes **and** source syntax/OPEN status for every unmatched original `ClassDef`. Overlay retrieved exact/substring literal keys, case comparisons, parallel function names, item accesses, similar parameter bags and forwarding on these canonical owners; do not discard a lead merely because it has no class match. Collect original **definitions/writes** and **reads/dispatch/calls** with lexical owners and source positions. Mark serialized schema, UI, transport and external protocol boundaries separately. Keep every unmatched class/site, duplicate, dynamic, unsupported or alternative row visible. Rank candidate cohorts with an **ordinal evidence tuple**, not a fabricated probability: original unique nominal/typed-case witness; independently writable repetition; ordered branch and canonical Call; cross-consumer corroboration; then penalties for OPEN binding or alternative owners. Substring overlap only boosts retrieval and never crosses a binding or domain/schema/UI role boundary. Report supporting original indices and the unjoined class/roster/arm/Call/dynamic rows, not merely a selected score. Now let the agent name bounded domain questions, cases and externally observable answers (including errors/unknowns) from these joined facts; it must not require a user-provided noun to start discovery.

NRA can establish source declarations and some exact lexical/callee bindings; it does **not** turn an equal spelling into live import identity, dict semantics, same runtime receiver, effect-free property or complete caller census. A nested function belongs to its executable lexical context, not automatically to the surrounding class's direct method family. Reconstruct ordered `if`/`elif`/`else` from original source spelling and preserve preceding/succeeding priority roots and fallthrough. If an effect or binding is OPEN, say so rather than guessing its owner.

## 3. Agent traces each answer backward to its determining declaration

**Do this work without asking the user to trace it.** For every consumer, the agent asks: **which declaration(s) or construction(s) can currently change this answer, and which producer(s) could legitimately determine it?** Multiple independent writable sources are the suspected mirror, not a reason to force one owner prematurely. Walk original source from consumer through factory, serializer, adapter, cache and registration to definitions and writes; use NRA's existing lexical/call authority when it can resolve an edge. Draw `determiner → derived consumer` only for established derivations. When an edge is unresolved, retain the source row and a typed OPEN reason, then inspect nearby tests/callers/history to resolve it where possible. Annotate roles:

- **Determining authority:** a declaration/construction boundary intentionally establishes this fact and its invariants.
- **Derived view:** mechanically computed from that authority; a lookup map derived from a tuple is not a second writable roster.
- **Independent replica:** the same admitted answer is authored again and can drift when the owner changes.
- **Separate role:** similar current values but a named independent future (e.g. a UI widget choice versus domain validation, a setup compiler versus backend module). Keep another owner.
- **OPEN:** source/alias/dynamic/phase/runtime relation has not been proved. Do not silently promote it to a derived view or an obligation.

Do not use “one owner” to merge all fact families. One *admitted fact* has one determining authority; several independent providers, protocol adapters and UI owners can coexist.

## 4. Try to falsify the proposed owner

Run a **new-case thought experiment**: add one member/field/module, change one alias, or make a valid unknown input. Which authored sites would need coordinated edits? If a second manual list must be updated, the proposed owner did not eliminate the mirror. If a different role may legitimately change without the first, name that divergence before merging them. Test an absent case, duplicated declaration, rebinding, fallback, reordered guard, alternate caller and subclass override—not only matching happy-path literals.

A public parent contract is justified only if its required operations and substitutability hold for admitted descendants. Verify MRO/constructor/descriptor and method-lookup consequences before choosing inheritance/MI. Prefer a public ABC and case-owned classes for behavior-bearing families; retain an enum when it has an independently justified value-only/boundary role. A domain object may own parameters previously threaded through helpers. None is automatic from a literal match. A service that merely relocates the same dispatch has not established domain ownership.

## 5. Admit a bounded relation or abstain

Produce a short receipt with `domain question | cases | required/forbidden implementation–consumer/class pairs | candidate determining declaration(s) | original evidence | derived/replica/separate/OPEN classifications | unknown/fallback | new-case edit test | adjudication authority`. Mark pairs **provisional** while contested or unsupported. The agent proposes and justifies ownership using source, tests and historical contrasts, but cites the supplied rule or task-authorized specification/declaration that licenses each required or forbidden pair. It may fill entailed pairs without asking the user to enumerate them; source similarity and an LLM's confidence are not independent domain authority. A missing source witness is **OPEN or out-of-bound**, never a forbidden pair without an explicit positive domain decision. Investigate ambiguity first; ask the user only the minimal set of precise questions for genuinely unavailable product/domain choices, stating the best supported alternatives and their consequences. Without admitted pairs/owners, output the agent's ranked answer plus specific OPEN blockers and an exploratory plan at most, not a prescriptive refactor. After admission, use the existing DSL and independent architecture/behavior gates in [ownership-to-dsl.md](ownership-to-dsl.md).

### Counterchecks

- **Class coverage:** `def factory(): class Hidden: ...` and `if flag: class Conditional: ...` remain original syntax rows even when the compact family index does not admit them. Do not report them as indexed descendants or silently drop them from the selected corpus.

- **#60:** `CELLPROFILER_MODULE_SEMANTICS_FAMILY_SPECS` and alias specs were independently authored; lookup maps derived from them were not. Runtime policy specs carried `Crop`'s different label keyword. The observed move toward `CellProfilerModule` declarations is a candidate owner of backend-module facts, **not** proof setup-only `SetupModuleCompiler` roles or unknown→processing fallback belong to that same family. A new backend module exposes whether manual tuples still need edits.
- **Toad:** `Setting.type`, `SchemaDict["type"]`, `Schema.key_to_type`'s seven-key local map and `SettingsScreen`'s nested UI branch share spellings but can answer different schema/domain/presentation questions. Ask whether a domain `Setting` variant owns validation/default coercion while Textual widget selection remains a UI adapter; do not fabricate a seven-subclass obligation or merge separate `if` roots. Track malformed external types and dynamic map access before any rewrite.
