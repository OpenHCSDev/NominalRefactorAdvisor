# Finding the determining owner, not just a matching class

**The agent does this whole investigation** and hands back a proposed owner with source receipts. Don't give the user steps 1–4 as homework. This is a skill workflow, not a new NRA detector or a new source of truth. Fix the checkout/import roots, the source revision, the scope and what you're excluding as unknown or dynamic. Reuse NRA's `SourceModule`, `ModuleSyntaxIndex`, canonical class-family index, lexical bindings, original Call/product-flow and existing detector evidence. Never build a competing parser, call registry or class roster. Write down the task rules and what the task says to do (specs, declarations), then pick a **source/revision/import-root corpus**, using the user's scope or cheap search to find candidate modules. You can start discovery before the relation is complete, but never override what the task says. If a proposed owner depends on other modules, widen the scan.

## 1. Bound the corpus; census classes first

Use existing NRA observations/findings, exact-string matches, substring overlap, helper prefixes and targeted search to pick or rank a corpus. False positives are fine for retrieval. **Before you interpret any hit**, collect *every original* `ast.ClassDef` row using NRA's `module_syntax_index(parsed.module).indexed_nodes_of_type(ast.ClassDef)` (the one existing parse/syntax authority). Join only eligible, uniquely matched declarations to the canonical compact class-family index for indexed ancestry, ABC/Enum/dataclass roles, fields and methods. That index only walks direct module/class-body declarations. It does **not** see function-nested or conditional/control-flow classes. Keep those, and any ambiguous or unmatched original `ClassDef` rows, as explicit unprojected OPEN rows. Don't invent indexed owners for them. Also keep index-admitted and unprojected classes that match no string/helper, as alternative-owner/counterevidence rows. After this class census and the residual overlay, the agent proposes more candidate domain questions itself, without replacing questions the task already fixed. Examples: "What input label keyword does this CellProfiler module require?", "Which setting value type is accepted?", "Who owns the saved parameter state?" List the cases/states and what callers can observe, including unknown input and errors. A class, filename, repeated string or guessed pattern is not the question. The same value can answer different questions at different phases (wire schema vs parsed domain vs UI presentation).

## 2. Overlay residual syntax on the complete class census

Keep original definition order, decorators, defaults, class-body/module rebinding and registered declarations for all index-admitted classes, **plus** source syntax/OPEN status for every unmatched original `ClassDef`. Lay retrieved exact/substring literal keys, case comparisons, parallel function names, item accesses, similar parameter bags and forwarding over these canonical owners. Don't drop a lead just because it has no class match. Collect original **definitions/writes** and **reads/dispatch/calls** with lexical owners and source positions. Mark serialized schema, UI, transport and external protocol boundaries separately. Keep every unmatched class/site, duplicate, dynamic, unsupported or alternative row visible. Rank candidate cohorts with an **ordinal evidence tuple**, not a made-up probability: original unique nominal/typed-case witness; independently writable repetition; ordered branch and canonical Call; cross-consumer corroboration; then penalties for OPEN binding or alternative owners. Substring overlap only boosts retrieval. It never crosses a binding or domain/schema/UI role boundary. Report the supporting original indices and the unjoined class/roster/arm/Call/dynamic rows, not just a winning score. Now the agent names the domain questions, cases and observable answers (including errors/unknowns) from these joined facts. It must not wait for the user to hand it a noun.

NRA can establish source declarations and some exact lexical/callee bindings. It does **not** turn equal spelling into live import identity, dict semantics, same runtime receiver, effect-free property or a complete caller census. A nested function belongs to its own executable context, not automatically to the surrounding class's method family. Rebuild ordered `if`/`elif`/`else` from the original source spelling and keep the priority roots before and after it, plus fallthrough. If an effect or binding is OPEN, say so. Don't guess an owner.

## 3. Agent traces each answer backward to its determining declaration

**Do this yourself. Don't ask the user to trace it.** For every consumer, ask: **which declaration(s) or construction(s) can change this answer today, and which producer(s) should legitimately determine it?** Several independent writable sources is your suspected mirror. It's not a reason to force a single owner early. Walk the original source from consumer through factory, serializer, adapter, cache and registration to definitions and writes. Use NRA's existing lexical/call authority when it can resolve an edge. Draw `determiner → derived consumer` only for derivations you've established. When an edge is unresolved, keep the source row and a typed OPEN reason, then check nearby tests/callers/history to resolve it if you can. Label each role:

- **Determining authority:** a declaration/construction boundary that deliberately establishes this fact and its invariants.
- **Derived view:** computed mechanically from that authority. A lookup map derived from a tuple is not a second writable roster.
- **Independent replica:** the same answer authored again, which will drift when the owner changes.
- **Separate role:** current values look alike but there's a named independent future (e.g. a UI widget choice versus domain validation, a setup compiler versus a backend module). Keep another owner.
- **OPEN:** nobody has proved the source/alias/dynamic/phase/runtime relation. Don't quietly promote it to a derived view or an obligation.

Don't use "one owner" to merge every fact family. One fact has one determining authority. Several independent providers, protocol adapters and UI owners can coexist.

## 4. Try to break the proposed owner

Run a **new-case thought experiment**: add one member/field/module, change one alias, or feed a valid unknown input. Which authored sites need coordinated edits? If a second manual list has to be updated, your owner didn't kill the mirror. If a different role can legitimately change without the first, name that split before you merge them. Test an absent case, a duplicated declaration, rebinding, a fallback, a reordered guard, another caller and a subclass override. Happy-path literal matches aren't enough.

A public parent contract is only justified if its required operations and substitutability hold for the descendants you're accepting. Check MRO/constructor/descriptor and method-lookup consequences before you pick inheritance/MI. Prefer a public ABC and case-owned classes for families that carry behavior. Keep an enum when it has its own value-only/boundary role. A domain object may own parameters that used to be threaded through helpers. None of this is automatic from a literal match. A service that just moves the same dispatch somewhere else hasn't established domain ownership.

## 5. Declare a bounded relation or back off

Produce a short receipt: `domain question | cases | required/forbidden implementation–consumer/class pairs | candidate determining declaration(s) | original evidence | derived/replica/separate/OPEN classifications | unknown/fallback | new-case edit test | who decides`. Mark pairs **candidate** while they're contested or unsupported. The agent proposes and justifies ownership from source, tests and historical contrasts, but for each required or forbidden pair it cites the task rule or the declaration/spec the task points to. It can fill in the pairs that follow without asking the user to list them. Source similarity and the LLM's confidence are not independent domain authority. A missing source witness is **OPEN or out of scope**. It is never a forbidden pair unless someone made an explicit positive domain decision. Investigate ambiguity first. Then ask the user only the minimal set of precise questions for product/domain choices you genuinely can't get elsewhere, with the best-supported alternatives and what each costs. Without accepted pairs/owners, give a ranked answer, the specific OPEN blockers and at most an exploratory plan. No real refactor. After the relation is accepted, use the existing DSL and the independent architecture/behavior gates in [ownership-to-dsl.md](ownership-to-dsl.md).

### Counterchecks

- **Class coverage:** `def factory(): class Hidden: ...` and `if flag: class Conditional: ...` stay as original syntax rows even when the compact family index skips them. Don't report them as indexed descendants, and don't quietly drop them from the corpus.

- **#60:** `CELLPROFILER_MODULE_SEMANTICS_FAMILY_SPECS` and the alias specs were independently authored. The lookup maps derived from them were not. Runtime policy specs carried `Crop`'s different label keyword. The move toward `CellProfilerModule` declarations is a candidate owner for backend-module facts. It does **not** prove that setup-only `SetupModuleCompiler` roles or the unknown→processing fallback belong to that family. Add a new backend module and see whether manual tuples still need edits.
- **Toad:** `Setting.type`, `SchemaDict["type"]`, `Schema.key_to_type`'s seven-key local map and `SettingsScreen`'s nested UI branch share spellings but can answer different schema/domain/presentation questions. Ask whether a domain `Setting` variant should own validation/default coercion while Textual widget selection stays a UI adapter. Don't invent a seven-subclass obligation or merge separate `if` roots. Track malformed external types and dynamic map access before any rewrite.
