# Domain decision receipts: theory and source-calibrated cases

Read the maintained `../../../docs/source/development/semantic_derivation_protocol.rst` (especially phases 0–3 and 7), `../../../docs/source/development/nominal_architecture_playbook.rst`, and the current sources before changing architecture. The OOPSLA preprint *Semantic Completeness for Correct Maintenance: A Strict Hierarchy of Typing and Inheritance* motivates a **task-relative** required-answer relation: for bounded domain meanings/states `D` and required questions `Q`, can the chosen representation derive every admitted answer without confusing states with different answers? Matching current values or counting classes cannot establish shared future meaning. Inheritance is one possible mechanism; admitted obligations, lookup and substitution decide whether it fits.

## Reusable latent refactor structure extracted from the PR transitions

These are **search and plan-shaping transformations** the agent applies itself, not hard-coded answers for another domain:

| Observed maintenance shape | Candidate ownership move | Check before prescribing |
|---|---|---|
| An existing nominal declaration plus independently hand-authored names/aliases/policies that must evolve together (#60) | Put the *admitted* fact and variant-specific behavior on its declaring member/class; derive lookup, exports and adapter projections; remove the independent roster. | Separate genuinely different owner families (setup vs backend), aliases, exceptional leaf hooks, unknown inputs and dynamic registration; derived lookup maps are not mirrors. |
| Repeated concrete-type/`hasattr` choices in UI managers (#44) | Name the actual capability question; where a public family can satisfy it, move shared invariant to the nominal contract and irreducible hook to a substitutable leaf; keep a framework adapter when that is its own role. | A service that still switches by concrete Qt type is only relocation. Reset/read-only can be separate questions; old guarded and new unguarded fallbacks differ. |
| Apparent state in a view and later `self.state` forwarding (#58) | **If** lifecycle, identity and domain obligations support it, consider an `ObjectState` owner for admitted state facts and derive view projections. | Separate conditional callers, nested state, descriptors, callbacks and saved/live phases mean source spelling alone cannot prove one live object or move every transition. |
| A declaration appears authoritative while consumers re-infer facts at runtime (separate #60 compiler/runtime cutover) | Ask whether a typed plan could derive the admitted answers at the longest *correct* lifetime, with runtime consuming it rather than re-inferring them. | The exact source transition retains `.setdefault` and other OPEN behavior; census residual runtime heuristics, source identity, evaluation phase and ABI before claiming parity or removal. This is separate from the CellProfiler family migration. |

Agent procedure: **select** a source/revision/import-root corpus (NRA or cheap literal/substring/name searches can rank candidate files) → **census every original `ClassDef`** via shared syntax index and join index-admitted class-family owners (retain unmatched/conditional/nested rows OPEN) → **overlay** residual decision sites → **name** candidate domain questions → **trace** answer provenance to each possible determining source → **separate** replicas from legitimate independently varying roles → **propose** a bounded `R*` and falsify it with a new case, unknown input and counterexamples → **admit** under task authority or retain OPEN → **express** the chosen move in NRA's existing staged DSL and independently validate architecture and behavior. Heuristics supply recall; the chosen owner and required relations are agent reasoning constrained by source; NRA preflight/simulation supplies mechanical leverage only after that choice. Do not ask the user to perform the trace.

## Agent's decision receipt (reasoning worksheet, not an NRA wire schema)

1. **Boundary and role names:** exact checkout and source/dependency revisions, bounded context, domain noun(s), lifetime/phase, independent future variation and same-shape/different-meaning collisions.
2. **Source witnesses:** original declaration, method, branch, caller, fallback and consumer rows. Distinguish independently writable rosters from maps derived from them; distinguish schema, domain, UI and transport authority. Retain unmatched, dynamic, alias, duplicate/rebound and OPEN rows with the reason each is unresolved.
3. **Candidate `R*`:** provisional required and forbidden implementation–consumer/class pairs, proposed determining authority *per fact family*, needed public parent contract or alternative owner, derived projections, named exceptions and residual boundaries. A nonexistent subtype is not itself a missing obligation.
4. **Decision:** `propose`, `alternative` or `abstain`; cite source evidence, describe why independent maintenance shrinks, and name counterevidence and admission conditions. An LLM can make an evidence-backed bounded-domain judgment when authorized; escalate contested meaning. No judge's confidence, historical diff or repeated spelling establishes behavioral equivalence.
